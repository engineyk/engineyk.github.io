# 总览

**Nanite** = Nanite Virtualized Geometry，UE5 的**虚拟微多边形几何**系统。核心目标：
- 以**像素级**三角形为渲染粒度，支持"海量几何 + 高精度模型"实时渲染
- 通过**预处理构建** + **GPU-Driven 渲染管线**消除传统 LOD / DrawCall / 面数瓶颈
- 不使用 Geometry Image，而是以 **Cluster / ClusterGroup / Page** 三级粒度组织数据

整体流程分两大阶段：

```
【离线 Build 阶段】                 【运行时 Render 阶段】
 HiRes Mesh                         GPUScene / Streaming
    │                                       │
    ▼                                       ▼
 ClusterTriangles  (METIS 图划分)    ┌── Instance 级裁剪
    │                               │
    ▼                               ├── Cluster 级 HZB 遮挡裁剪（两遍）
 BuildDAG          (多级 LOD)       │
    │                               ├── Rasterize：SW(CS) + HW(PS) 混合
    ▼                               │   输出 Visibility Buffer(64bit)
 NaniteEncode      (Page 压缩)      │
    │                               ├── EmitDepthTargets：Depth/Mask/MaterialDepth
    ▼                               │
 FResources                         ├── Nanite BasePass → GBuffer
 (PageStream/Hierarchy/Imposter)    │
                                    └── RenderLights / VSM / Lumen / TSR
```

# Cluster

## 定义

- **Cluster** 是一组**相邻三角形的集合**（UE 中默认上限 `FCluster::ClusterSize = 128` 三角形），是 Nanite 的最小调度单元。
- Cluster 并非 UE 独创，育碧 / 寒霜等引擎早已使用，但 UE 做到了**"基于 Cluster 的可持续 LOD"**。

## 为什么用 Cluster

- **粒度合适**：比整网格细，比逐三角形粗，适合 GPU Wavefront / SIMD 调度
- **可合批**：相邻 Cluster、相邻 LOD 的 Cluster 可动态合并，避免 LOD 跳变
- **Locality**：同一 Cluster 内三角形空间连续，光栅化缓存命中率高
- **独立单元**：可独立做 Frustum / HZB / BackFace / SmallTri 裁剪

## 主要结构
详见 `Cluster/FCluster.md`、`Cluster/FPackedCluster.md`。

| 结构                 | 作用                                                             |
| -------------------- | ---------------------------------------------------------------- |
| `FCluster`           | 构建期的 Cluster（完整顶点/索引/边/邻接/Bounds/Error）           |
| `FPackedCluster`     | 运行时 GPU 上的 128 字节压缩结构（位压缩）                       |
| `FClusterGroup`      | 多个 Cluster 组成的 Group，是 **DAG 的节点**，LOD 选择的最小单位 |
| `FClusterGroupPart`  | Group 跨 Page 时的分片                                           |
| `FClusterFixup`      | 跨 Page 引用修正（Page 流式加载后必须 patch）                    |
| `FClusterDiskHeader` | 磁盘上的 Cluster 头（解码用）                                    |

## ClusterGroup 与 DAG

- **ClusterGroup** 由 8~32 个相邻 Cluster 组成（`MinGroupSize ~ MaxGroupSize`）
- 对 Group 整体做**减面**，再重新划分为新的子 Cluster → 得到更粗 LOD 的 Cluster
- 所有层级通过父子关系形成一个**有向无环图（DAG）**，每级称为一个 **MipLevel**

这样 Cluster 数量随 Mip 指数递减（类似 Texture Mipmap），**LOD 选择即 Cluster 选择**，且在 Group 边界上**共享顶点**，消除了 LOD 间接缝。

# Build

Nanite 的离线构建以 `NaniteBuilderModule::Build` 为入口（`Engine\Source\Developer\NaniteBuilder\Private\NaniteBuilder.cpp`），主要优化手段：

- 大量 `ParallelFor` 并行化（边哈希、邻接查找、Cluster 构建、DAG Reduce）
- 使用 **METIS** 第三方库做高质量图划分
- 多级概念（Cluster / ClusterGroup / Part）组织数据
- 使用 **DAG + Mip Level + Coarse Representation** 加速 LOD 构建
- 预生成 **Page / Hierarchy / ImposterAtlas** 以便 GPU 直接使用
- 大量压缩：**LZ 压缩 + 定点数量化 + 位域打包**

## 管线总览

```cpp
bool FBuilderModule::Build(Resources, Vertices, Indices, Sections, ...)
{
    // 1. 三角形 → 材质索引映射（烘入 FMaterialTriangles）
    // 2. BuildNaniteData：对每个 Section 执行 ClusterTriangles
    //    └─ METIS 图划分 → 初级 Cluster 列表
    // 3. 可选：bUseCoarseRepresentation → BuildCoarseRepresentation
    // 4. 对每个 Section 调用 BuildDAG：自底向上逐级减面，构造 DAG
    // 5. Encode(Resources, Settings, Clusters, Groups, ...)
    //    ├─ RemoveDegenerateTriangles
    //    ├─ BuildMaterialRanges
    //    ├─ ConstrainClusters
    //    ├─ CalculateQuantizedPositionsUniformGrid
    //    ├─ CalculateEncodingInfos
    //    ├─ AssignClustersToPages
    //    ├─ BuildHierarchies
    //    └─ WritePages
    // 6. 可选：bGenerateImposter → 将叶 Cluster 光栅化到 FImposterAtlas
}
```

## ClusterTriangles（底层 Cluster 生成）

1. **构建边哈希**：`ParallelFor` 遍历所有 Index，用 `EdgeHash.Add_Concurrent` 并行入表
2. **查找共享边/边界边**：并行匹配反向边，识别出 BoundaryEdges 与内部邻接
3. **并查集（FDisjointSet）** 合并连通分量，避免跨连通分量合并三角形
4. **FGraphPartitioner.PartitionStrict**：调用 METIS 做图划分，每块为 `[ClusterSize-4, ClusterSize]` 三角形
5. 并行构造 `FCluster`，叶子 Cluster 的 `EdgeLength` 乘 -1 作为标记

## BuildDag

DAG 的作用：**预生成所有 LOD 层级**，运行时只需按屏幕误差挑选 Cluster。

源码：`Engine\Source\Developer\NaniteBuilder\Private\ClusterDAG.cpp`

### 算法流程（自底向上逐层构造）

```bash
Level 0 = ClusterTriangles 生成的叶 Cluster
repeat:
    if LevelClusters <= MaxGroupSize:
        所有 Cluster 合成 1 个 Group → DAGReduce → 产生父 Cluster
        break（到达根）
    else:
        ① 构建 ExternalEdgeHash（并行）
        ② 在其它 Cluster 查找匹配反向边 → AdjacentClusters（并行）
        ③ DisjointSet 合并连通的 Cluster
        ④ FGraphPartitioner 以"共享边数×权重 + 位置链接"为代价做图划分
           PartitionStrict(MinGroupSize, MaxGroupSize)  // 典型 8~32
        ⑤ 每块 → 1 个 FClusterGroup
        ⑥ 并行 DAGReduce(Group)：
             - 合并 Group 内所有 Cluster 的三角形
             - MeshSimplifier 减面到 ~50%
             - 重新 PartitionStrict 为新 Cluster（父 Cluster）
             - 记录 MaxParentLODError（运行时 LOD 选择用）
             - 在 Group 边界顶点上**锁定**，保证与相邻 Group 接缝不裂
    LevelOffset = 当前层末尾
最后：构造 RootClusterGroup，MipLevel 为根层 +1
```

### 关键实现要点

- **确定性排序**：`RadixSort32` 按 `GUID` 排序，保证构建结果在多线程下稳定
- **邻接权重**：`NumSharedEdges * (bSiblings ? 1 : 16) + 4`，优先把非同组的强相邻 Cluster 聚到一起
- **位置连接**（`BuildLocalityLinks`）：连通分量外再加空间近邻边，避免 Cluster 在空间上过度分散
- **DAGReduce 核心**：见 `Build/BuildDAG/DAGReduce.md`
- **根节点**：最后一层只剩 1 个 Cluster 时，单独封装为 `RootClusterGroup`

### DAG 结构示意
```
                  Root (MipN)
                 /    |    \
             G_a    G_b    G_c          ← 粗 LOD
            /  \    / \    /  \
           ...  ... ... ... ... ...     ← 中 LOD
          /                         \
      G_leaf0   G_leaf1  ...   G_leafK  ← 叶子 Group
       / | \                     / | \
      C0 C1 C2                  Cn Cn+1 Cn+2  ← 原始 Cluster
```

运行时选 LOD：从根向下遍历，命中条件为 `ParentError > Threshold && MyError <= Threshold`，以此保证 **屏幕投影误差 < 1 像素**。

## NaniteEncode

源码：`Engine\Source\Developer\NaniteBuilder\Private\NaniteEncode.cpp`

目标：把构建阶段得到的 Cluster / Group 压缩为运行时可直接流式加载的 **Page** 数据。

### 子步骤

| 子步骤                                   | 作用                                                                                               |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `RemoveDegenerateTriangles`              | 删除 `i0==i1 \|\| i0==i2 \|\| i1==i2` 的退化三角形（并行）                                         |
| `BuildMaterialRanges`                    | 按材质对 Cluster 内三角形排序，生成 `FMaterialRange[]`，Render 阶段用于 Material Depth             |
| `ConstrainClusters`                      | 将 Cluster 的顶点数/三角形数约束到编码上限，必要时拆分                                             |
| `CalculateQuantizedPositionsUniformGrid` | 用**均匀网格量化**位置，确定 `PositionPrecision`（见 `CalculateQuantizedPositionsUniformGrid.md`） |
| `CalculateEncodingInfos`                 | 计算每个 Cluster 的位宽（位置/法线/UV/颜色各占多少位）                                             |
| `AssignClustersToPages`                  | 把 Cluster 打包到 Page（默认 128KB），优先同 Group 同 Page；跨 Page 时产生 `FClusterGroupPart`     |
| `BuildHierarchies`                       | 构造 BVH 风格的 `FPackedHierarchyNode`，GPU 裁剪时自上而下遍历                                     |
| `WritePages`                             | 位压缩并 LZ 压缩写入最终二进制；生成 `FClusterFixup` 用于运行时 patch                              |

### 编码压缩要点

- **位置**：量化到统一网格，`PositionPrecision` 是 log2 最小间隔，一个坐标通常 14~21bit
- **法线**：八面体编码 + 位压缩（12~16bit/法线）
- **UV**：相对 Cluster 包围盒量化，每 UV 通道独立位宽
- **索引**：`FCluster::ClusterSize` 上限 128，6bit 即可
- **材质**：运行时通过 `MaterialRange[]` + 三角形所在区间查询

### Visibility Buffer 结构

运行时光栅化写入的 `VisBuffer64`：

```bash
[63:32]  Depth (32bit)
[31: 7]  ClusterID (25bit)   // 可支持 33M 个活跃 Cluster
[6 : 0]  TriangleIndex (7bit)// ClusterSize ≤ 128
```

### Page / Hierarchy / Imposter

- `FPage`：最终输出的字节数组，可单独流式传输
- `FHierarchy`：`FPackedHierarchyNode` 的数组，GPU 裁剪 `PersistentCull.usf` 的输入
- `FImposterAtlas`：`NumMeshes==1` 时生成，远距离时用 2D 图片代替几何

# NaniteRender

源码入口：`Engine\Source\Runtime\Renderer\Private\Nanite\NaniteRender.cpp`

Nanite 渲染穿插在传统 DeferredShadingSceneRenderer 管线中，每帧时序：

```bash
UpdateAllPrimitiveSceneInfos → GGlobalResources.Update
 → GStreamingManager.BeginAsyncUpdate     (Nanite Page 流入)
 → GPUScene.Update / UploadDynamicPrimitives
 → InstanceCullingManager.CullInstances   (Instance 级裁剪)
 → GStreamingManager.EndAsyncUpdate
 → RenderPrePass                          (非 Nanite 物体的 Prepass)
 ┌──────────── 对每个 View ────────────┐
 │  InitCullingContext + InitRasterContext
 │  CullRasterize                                       ← Culling + Raster
 │  EmitDepthTargets                                    ← 写 Depth/Mask/MatDepth/Velocity
 │  BuildHZBFurthest                                    ← 为下一帧/后通道准备 HZB
 │  ExtractResults
 └──────────────────────────────────────┘
 → RenderBasePass  (含 Nanite::DrawBasePass → GBuffer)
 → GStreamingManager.SubmitFrameStreamingRequests
 → RenderLights    (Nanite 光照融入传统管线)
 → RenderTranslucency / PostProcessing / TSR / VSM
```

## Culling

Nanite 裁剪是**纯 GPU-Driven**，全部用 Compute Shader 完成，CPU 零提交开销。

### 多级裁剪粒度

| 粒度                               | 目的                                         | 入口                                    |
| ---------------------------------- | -------------------------------------------- | --------------------------------------- |
| Primitive（`FPrimitiveSceneInfo`） | 传统可见性                                   | `FSceneRenderer::ComputeViewVisibility` |
| **Instance**                       | `FInstanceCullingManager::CullInstances`     | `CullInstances.usf`                     |
| **Hierarchy Node（BVH）**          | 遍历 `FPackedHierarchyNode` 做 Frustum + HZB | `NodeAndClusterCull.usf`                |
| **Cluster**                        | Cluster 级 Frustum + HZB + LOD 选择          | 同上                                    |
| **Triangle**                       | Rasterize 内部 BackFace + SubPixel 剔除      | `Rasterizer.usf`                        |

### 两遍遮挡剔除（Two-Pass Occlusion）

关键源码：`CullRasterize` 中的 `bTwoPassOcclusion` 分支

```bash
第 1 遍（Main Pass）：
    用「上一帧 HZB」做遮挡剔除
    └─ AddPass_InstanceHierarchyAndClusterCull(CULLING_PASS_OCCLUSION_MAIN)
    └─ AddPass_Rasterize  → 光栅化"上一帧可见"的 Cluster
    └─ BuildHZBFurthest   → 用本帧光栅化结果构建 **最新 HZB**

第 2 遍（Post Pass）：
    用「本帧最新 HZB」再次检查 Main Pass 剔除的 Cluster
    └─ AddPass_InstanceHierarchyAndClusterCull(CULLING_PASS_OCCLUSION_POST)
    └─ AddPass_Rasterize  → 光栅化"上一帧不可见但本帧可见"的 Cluster
```

**优点**：既避免了传统 Query Occlusion 的 1 帧延迟，又保证了 Disocclusion（新出现的物体）不会丢失。

### LOD 选择（屏幕投影误差）

每个 `FClusterGroup` 记录 `MinLODError / MaxParentLODError / LODBounds`，GPU 端公式：

```c
float ProjectedEdgeScale = ComputeProjectedEdgeScale(LODBounds, ViewOrigin, ViewMatrix);
bool  bVisible   = (MyError      * ProjectedEdgeScale) <= Threshold  // 本级足够精细
               && (ParentError  * ProjectedEdgeScale) >  Threshold;  // 父级过粗糙
```

这样同一个 DAG 的**一次切片**恰好构成无接缝覆盖。

## Rasterize

源码：`AddPass_Rasterize` + `Rasterizer.usf`

### 软光栅（SW）与硬光栅（HW）混合

| 技术          | 三角形大小           | 实现                              | 优点                                                              |
| ------------- | -------------------- | --------------------------------- | ----------------------------------------------------------------- |
| **SW Raster** | 面积很小（几像素级） | Compute Shader，Persistent Thread | 避免 GPU Pixel Shader 的 **2×2 Quad Overdraw**（每像素一个 lane） |
| **HW Raster** | 大三角形             | 传统 VS+PS / MeshShader           | 利用固定管线的覆盖率/插值硬件                                     |

调度由 `RasterContext.RasterScheduling` 决定：

- `HardwareOnly`：全 HW
- `SoftwareOnly`：全 SW
- `HardwareThenSoftware`（默认）：运行时根据 Cluster 包围盒屏幕尺寸分派

### 输出：Visibility Buffer（64bit / 像素）

光栅化**不做真正的 Shading**，仅写：

```
VisBuffer64 = (Depth << 32) | (ClusterID << 7) | TriangleIndex
              ↑ 32bit        ↑ 25bit            ↑ 7bit
```

对比传统 BasePass 的 GBufferA/B/C/D/E，**IO 和显存大幅降低**，这本质就是 **Visibility Buffer** 技术。

### EmitDepthTargets

写回 4 类纹理：

| 纹理                         | 用途                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------ |
| **SceneDepth**               | 传统 DepthBuffer（融合传统/Nanite 场景）                                             |
| **NaniteMask** / **Stencil** | 标记哪些像素属于 Nanite，给 BasePass/Lighting 区分                                   |
| **Velocity**                 | 给 TSR / MotionBlur 提供屏幕速度                                                     |
| **MaterialDepth**            | **材质 ID 转换成的灰度深度值**，在 Nanite BasePass 中利用 **Early-Z** 按材质过滤像素 |

### BasePass

`Nanite::DrawBasePass`：

- 从 `VisBuffer64` 读取 `ClusterID + TriangleID` → 索引到 `FPackedCluster`
- **运行时重建** Position / Normal / UV（切线在 PS 动态计算以节省存储）
- 以**全屏 Pass**方式按 Material 分组绘制，利用 MaterialDepth + Early-Z 使每像素只跑命中材质
- 输出常规 GBufferA/B/C/...，之后与传统物体**共用光照管线**

## Lighting

UE5 的 `RenderLights` 相比 UE4 基本不变，Nanite **不侵入光照管线**，只通过 GBuffer + NaniteMask 参与：

```cpp
void FDeferredShadingSceneRenderer::RenderLights(...)
{
    // Strata（分层材质）模板初始化（UE5 新增）
    if (Strata::IsStrataEnabled() && Strata::IsClassificationEnabled())
        Strata::AddStrataStencilPass(GraphBuilder, Views, SceneTextures);

    // NonShadowedLights：无阴影光源
    // ShadowedLights：
    //   ① 阴影投射：RenderDeferredShadowProjections
    //      - VSM（VirtualShadowMap）替代传统 CSM/Static/Preview/PerObject/Movable Shadow
    //      - SMRT（Shadow Map Ray Tracing）做半影/软阴影/接触阴影
    //   ② 光照着色：RenderLight
}
```

### VSM（Virtual Shadow Map）

- 虚拟分辨率 **16384² × 多 Clipmap**，按需分页驻留在 Physical Shadow Page Pool
- **与 Nanite 完美配合**：Nanite Cluster 可以被**任意 ShadowView** 直接做 Culling + Raster（`CullRasterize` 接受 `VirtualShadowMapArray*`）
- Page Flags 决定哪些 Page 需要本帧更新，**天然缓存**：静态场景几乎 0 成本
- 详见 `NaniteRender/Lighting/VSM.md`

### Lumen
作为全动态 GI/反射系统，消费 Nanite 产生的 GBuffer + SurfaceCache，本文不展开。

## Render（综合管线串联）

`FDeferredShadingSceneRenderer::Render` 关键节选（省略非 Nanite 逻辑）：

```cpp
void FDeferredShadingSceneRenderer::Render(FRDGBuilder& GraphBuilder)
{
    const bool bNaniteEnabled = UseNanite(ShaderPlatform) && ViewFamily.EngineShowFlags.NaniteMeshes;

    Scene->UpdateAllPrimitiveSceneInfos(GraphBuilder, true);
    FGPUSceneScopeBeginEndHelper GPUSceneScope(Scene->GPUScene, GPUSceneDynamicContext, Scene);

    if (bNaniteEnabled) {
        Nanite::GGlobalResources.Update(GraphBuilder);              // 全局资源环形缓冲
        Nanite::GStreamingManager.BeginAsyncUpdate(GraphBuilder);   // 异步 Page 流入
    }

    FInstanceCullingManager InstanceCullingManager(GInstanceCullingManagerResources, Scene->GPUScene.IsEnabled());
    InitViews(GraphBuilder, ..., InstanceCullingManager);

    Scene->GPUScene.Update(GraphBuilder, *Scene);
    for (auto& View : Views) Scene->GPUScene.UploadDynamicPrimitiveShaderDataForView(GraphBuilder, Scene, View);
    InstanceCullingManager.CullInstances(GraphBuilder, Scene->GPUScene);

    if (bNaniteEnabled) Nanite::GStreamingManager.EndAsyncUpdate(GraphBuilder);

    RenderPrePass(GraphBuilder, SceneTextures.Depth.Target, InstanceCullingManager);

    TArray<Nanite::FRasterResults, TInlineAllocator<2>> NaniteRasterResults;
    if (bNaniteEnabled && Views.Num() > 0) {
        NaniteRasterResults.AddDefaulted(Views.Num());
        Nanite::FRasterContext RasterContext = Nanite::InitRasterContext(GraphBuilder, FeatureLevel, RasterTextureSize);

        for (int32 ViewIndex = 0; ViewIndex < Views.Num(); ViewIndex++) {
            const FViewInfo& View = Views[ViewIndex];

            Nanite::FCullingContext CullingContext = Nanite::InitCullingContext(
                GraphBuilder, *Scene,
                !bIsEarlyDepthComplete ? View.PrevViewInfo.NaniteHZB : View.PrevViewInfo.HZB,
                View.ViewRect,
                /*bTwoPassOcclusion*/ true, /*bUpdateStreaming*/ true,
                /*bSupportsMultiplePasses*/ false,
                /*bForceHWRaster*/ false,
                /*bPrimaryContext*/ true,
                /*bDiscardNonMoving*/ false);

            Nanite::FPackedView PackedView = Nanite::CreatePackedViewFromViewInfo(View, RasterTextureSize, VIEW_FLAG_HZBTEST, 3);

            // 裁剪 + 光栅化（GPU-Driven，含 Two-Pass HZB Occlusion）
            Nanite::CullRasterize(GraphBuilder, *Scene, { PackedView }, CullingContext, RasterContext, RasterState, nullptr, false);

            // 写回传统 Depth/Mask/MaterialDepth/Velocity
            if (bNeedsPrePass) {
                Nanite::EmitDepthTargets(GraphBuilder, *Scene, Views[ViewIndex],
                    CullingContext.SOAStrides, CullingContext.VisibleClustersSWHW, CullingContext.ViewsBuffer,
                    SceneTextures.Depth.Target, RasterContext.VisBuffer64,
                    RasterResults.MaterialDepth, RasterResults.NaniteMask, RasterResults.VelocityBuffer, bNeedsPrePass);
            }

            // 为 Post Pass / 下一帧建 HZB
            if (!bIsEarlyDepthComplete && bTwoPassOcclusion && View.ViewState) {
                FRDGTextureRef GraphHZB = nullptr;
                BuildHZBFurthest(GraphBuilder, SystemTextures.Black, RasterContext.VisBuffer64,
                                 PrimaryViewRect, FeatureLevel, ShaderPlatform, TEXT("Nanite.HZB"), &GraphHZB);
                GraphBuilder.QueueTextureExtraction(GraphHZB, &View.ViewState->PrevFrameViewInfo.NaniteHZB);
            }

            Nanite::ExtractResults(GraphBuilder, CullingContext, RasterContext, NaniteRasterResults[ViewIndex]);
        }
    }

    RenderBasePass(GraphBuilder, SceneTextures, DBufferTextures, BasePassDepthStencilAccess,
                   ForwardScreenSpaceShadowMaskTexture, InstanceCullingManager);
    if (bNaniteEnabled && bShouldApplyNaniteMaterials) {
        for (int32 ViewIndex = 0; ViewIndex < Views.Num(); ++ViewIndex) {
            Nanite::DrawBasePass(GraphBuilder, SceneTextures, DBufferTextures, *Scene,
                                 Views[ViewIndex], NaniteRasterResults[ViewIndex]);
        }
    }

    if (bNaniteEnabled) Nanite::GStreamingManager.SubmitFrameStreamingRequests(GraphBuilder);

    RenderLights(GraphBuilder, SceneTextures, ...);    // 融入 VSM / Lumen
    RenderTranslucency(GraphBuilder, SceneTextures, ...);
    AddPostProcessingPasses(GraphBuilder, View, PostProcessingInputs, NaniteResults, InstanceCullingManager);
}
```

# 限制与性能关注

## 支持组件

Static Mesh / Instanced Static Mesh / HISM / Geometry Collection。

## 不支持

- 骨骼动画 / Morph Target / World Position Offset / Spline Mesh
- 非 Opaque BlendMode（Masked、Translucent 都不行）
- 延迟贴花、线框模式、像素深度偏移、双面材质
- 自定义深度模板、实例顶点绘制
- 前向渲染、VR Stereo、分屏、MSAA、光通道
- 对 Nanite 网格做完整精度 RayTracing

## 注意

- Nanite 不存每顶点切线，**切线在 PS 运行时算**，边缘可能有不连续
- **Aggregate Geometry**（头发/树叶/草）：远距离会合成 Volume，影响 LOD 与遮挡
- **Closely Stacked Surfaces**：紧堆表面会被全部画出（Overdraw 风险）

# 小结

Nanite 不是单点技术，而是**一条完整的管线重构**：

1. **离线**：用 Cluster + ClusterGroup + DAG + Page 把"海量三角形"预处理成可流式、可选择、可合批的压缩数据；
2. **运行时**：用 GPU-Driven Culling（Instance→Hierarchy→Cluster→Triangle）+ SW/HW 混合光栅化 + Visibility Buffer 的延迟思路，把每像素的成本压到接近 **Depth-Only** 级别；
3. **融合**：BasePass 通过 `VisBuffer64 + MaterialDepth + Early-Z` 写常规 GBuffer，后续光照 / VSM / Lumen / TSR 全部与传统管线共享。

这套架构让 UE5 首次在"极高几何复杂度"与"实时帧率"之间取得平衡，但代价是：**仅限静态不透明几何**，且对 GPU 和平台驱动有较高要求。
